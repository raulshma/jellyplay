## Goal
Surface the existing settings search inside the homescreen's top search bar, with a user-configurable toggle (ON by default, in Appearance). Reuse the existing fuzzy matcher/registry via a clean module move — no duplication.

## Architecture decision: move search artifacts to `core/ui`
`SettingsSearchItem`, `SettingsSearchMatcher`, and `SettingsSearchRegistry` currently live in `feature/settings`, which `feature/home` cannot depend on. They depend only on `Route` (core/ui), tabler icons (core/ui), and pure Kotlin — all already in `core/ui`. Moving them is the DRY, single-source-of-truth fix. Only consumer today is `SettingsScreen` (+ the matcher test) — low blast radius.

- `git mv` these to `core/ui/src/main/java/com/raulshma/jellyplay/core/ui/settingssearch/`:
  - `SettingsSearchRegistry.kt` (contains `SettingsSearchItem` + `SettingsSearchRegistry`)
  - `SettingsSearchMatcher.kt`
- `git mv` `SettingsSearchMatcherTest.kt` → `core/ui/src/test/.../settingssearch/`
- Update package declarations + imports. `SettingsScreen.kt` import lines updated to new package.

## Performance
- Settings match is pure, off-main (Dispatchers.Default), sub-ms; gated entirely behind the toggle (zero cost when off).
- 120ms debounce (not 400ms) → instant settings results as you type while media still loads.
- All new lambdas hoisted with `remember` to preserve skippability during per-keystroke recomposition (existing overlay discipline).
- Stable LazyColumn keys; no new network calls.

## UI/UX
- Settings section appended after media (media stays primary intent on home), but appears instantly (no network wait).
- Tapping a settings result deep-links to the exact sub-screen + scroll-highlights the row (reuses `highlightSettingId` infra). Advanced items auto-enable "Advanced settings" then deep-link — parity with the Settings screen.
- Toggle discoverable both in Appearance and via settings search itself.
