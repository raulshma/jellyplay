# Architecture context

Orientation for engineers and coding agents new to JellyPlay; `GLOSSARY.md` is the companion vocabulary file (terms, idioms, defect rules), user-facing docs live in `docs/`. KMP migration is complete: features in `shared/feature/*` (commonMain + platform actuals), core in `shared/core/*` (former legacy modules' Android halves are `androidMain` source sets of `:shared:core:ui`/`:shared:core:data`, identical packages, Robolectric suites in `androidHostTest` lanes). Only Android-only module is the `:app` shell, beside `apps/desktop`. Room 3 (`androidx.room3`) on android/jvm. DI is Koin-only repo-wide. Paths relative to repo root.

Player code lives in two shared modules: `shared/core/player-contract` (engine-agnostic `MediaEngine` contract + engine-shared machinery) and `shared/feature/player-video` (VOD screen, VM, session collaborators). **Package↔module anomaly (recorded decision)**: ALL player-contract commonMain declares `com.raulshma.jellyplay.feature.player.video.engine` (zero import churn at the split); three files borrow other packages (`PlayerLifecycleCallbacks` + `RemotePlayableEngine` borrow `core.data`; `SessionPositionStore` keeps `feature.player.video` so the shared FakePositionStore satisfies it without a core→feature edge). Grepping by package cannot tell module — the edge is in player-contract's build.gradle.kts. New contract files keep the canonical feature package. `EngineStateChassis` (published flows, reset choreography, updateConfig dedup, buffer capacities as ctor params) is contract commonMain; `BasePlayerEngine` + `MpvDesktopEngine` extend it — a new published flow is declared once. Both shells register nav sections through `shared/feature/shell` (`appSections` + `ShellHostHooks` + registration ledger).

## Direct Play ↔ Transcode

PlaybackMode (core:model) = AUTO / FORCE_DIRECT_PLAY / FORCE_TRANSCODE. AUTO: server decides via PlaybackInfo against device profile + effective max bitrate from **AdaptiveBitrateManager** (core:data) — tiers 360p–4K, 2.5 Mbps metered cap, data-saver clamping, manual cap; adaptive disabled ⇒ cap null, server direct-plays anything decodable. FORCE_DIRECT_PLAY requests "direct play all" profile (static URL even for undecodable codecs); runtime failure trips the coordinator's one-shot fallback latch → session flips FORCE_TRANSCODE (persisted via PlaybackStore), stop-reports old session, reloads. FORCE_TRANSCODE re-encodes; reloadForMode surfaces "Switched to transcoded stream". TranscodeReasonsRefresher fetches live TranscodingInfo → PlayerSessionState.transcodeReasons → VM mirror (isDirectPlayForced mirrors mode the same way).
