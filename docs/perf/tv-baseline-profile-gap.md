# TV baseline-profile gap

**Status: known gap. TV starts are fully interpreted today — the tv flavor
ships no baseline profile, so every TV cold start JIT-compiles the boot path
on-device.**

## Why there is no TV profile

Baseline profiles are generated by the `:baselineprofile` producer module
(`BaselineProfileGenerator`), which runs the app on a Gradle Managed Device.
The generator declares a single `ciPixel8` phone GMD, and AGP cannot drive TV
system images on GMDs — `:app` therefore wires the producer into the phone
flavor only (`baselineProfile { variants { create("phone") { ... } } }` in
`app/build.gradle.kts`), and the tv variant has no producer at all. The
committed generated profiles live under `app/src/phoneRelease/generated/` and
are phone-only.

Running a real TV device/emulator through `useConnectedDevices = true` for the
tv flavor is the "proper" fix but is currently unautomation-friendly (no
headless lane, flaky swipes on D-pad UI, dedicated CI hardware).

## Options to close it (when TV startup work is prioritized)

1. **Hand-curated startup profile from the phone shell classes.** Take the
   shell/boot classes the phone `startup-prof.txt` covers (Application →
   MainActivity splash gate → shell host → first composed frame) and author a
   checked-in `app/src/tvRelease/baselineProfiles/baseline-prof.txt` covering
   those same classes. The TV boot path shares the phone shell graph, so the
   class list transfers; TV-specific surfaces (focus handling, leanback UI)
   would be added manually. Risk: drift — the file is hand-maintained and must
   be revisited whenever the shell boot path changes.
2. **Connected-device generation lane.** Flip the generator's `baselineProfile
   { useConnectedDevices = true }` behind a dedicated tv flavor producer and
   drive a long-running TV emulator on a CI runner. Highest fidelity, highest
   operational cost.
3. **Do nothing.** TV is a niche form factor here; JIT warmup cost is masked
   by longer TV session lifetimes.

Option 1 is the pragmatic first step if TV startup numbers ever matter: it is
a static file + one build.gradle change (`baselineProfile` wiring for the tv
variant), verifiable with `BaselineProfileAssertion.baselineProfileIsUsed` in
`:baselineprofile` run against a tv build.
