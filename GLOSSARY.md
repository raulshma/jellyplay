# JellyPlay glossary

Shared vocabulary for the client codebase: terms, idioms, and defect rules. Architecture detail lives in `CONTEXT.md`. The companion plugin's vocabulary (contract, capability probe, namespaces, tombstones, dispatch, resilient fetch…) lives in `jellyfin-plugin-jellyplay/GLOSSARY.md` and is not duplicated here. A "defect" note marks a shape the codebase forbids — usually source-scan or test pinned.

## State sync (client side)

**Sync reservation** — the `jpsync.*` key space (mirrors, cursors, per-namespace toggles, device id). One module owns the grammar; adapters/engine acquire keys through it, never raw literals. It is the one classifier of key kinds: a derived per-device payload beside settings (e.g. a widget's CW buffer) is never a setting, and its exclusion belongs to the reservation's policy — **a store hand-rolling its own exclusion is a defect**.

**Sync mirror** — the last-synced snapshot a `ProfileSyncAdapter` diffs against to detect dirty values. Exactly one implementation; every adapter delegates — **an adapter hand-rolling the comparison is a defect**.

**Mirror cycle read** — cycle-start mirror state: each adapter's dirty + tombstone faces read ONCE into a `CycleNamespaceState` (two mirror reads per adapter per cycle); pending face is arithmetic over cycle inputs, never a re-diff. A dirty value equal to remote resolves synced there, never pending forever. Interface stays commonMain (reads ride the two `ProfileSyncAdapter` verbs).

**Sync adapter base** — jvmShared base over the adapter↔mirror delegation seam (dirty/delete/markSynced, `deleteRemote` clear-tail, tombstone + key-agree rules). `MirrorProfileSyncAdapter` is the base; an adapter implements namespace/snapshot/applyRemote + deleteLocally hook. Interface commonMain, base jvmShared (mirror is). Tombstone-roaming namespaces override `deletedKeys`; delegating it for value-only namespaces would push resets as tombstones. Nine bindings multi-bind the interface; `ProfileSyncRepository` consumes them sorted by `REGISTRATION_ORDER` (Koin `getAll` on secondary binds is index-allocation order, not declaration — `DataKoinModulesTest` pins via `activeNamespaces`). Registration home `DataProfileSyncKoinModule`.

**Playlist row codec** — ONE home for smart/mood/moodpref row shape: `PlaylistRowCodec` owns entity↔payload↔domain (lenient JSON decode, wall-clock stamps) + criteria-blob schema; repositories' `toDomain`/`toEntity` and the backup slice mapper delegate. `{family}/{id}` key grammar one home beside `parseSlashKey` (`backupKey()`). JSON blobs stay opaque writer-produced strings.

## Plugin client

**Plugin role** — narrow consumer-facing interface over the one plugin client family (ADR-0010 §5): settings sync, device registry + push, analytics, transcodes, ratings, markers. One family impl satisfies all roles; consumers/fakes depend on the one role they use.

**Contract mismatch** — capabilities-probe refused-contract verdict: plugin answered but `contractVersion` outside `JellyPlayPluginStatusStore.KNOWN_CONTRACT_VERSIONS`. Status stays `UNAVAILABLE` (every gate fails closed like an absent plugin) while `contractMismatch` side channel carries served version + supported range + plugin version (settings banner + admin hint consume it). Range label is `supportedRangeLabel` on the mismatch type — **a second hand-fold of the range is a defect**. `servedPluginVersion` feeds the settings group summary.

**Library client families** — impl-side counterpart of consumer seams: small ctor-injected adapters over the one `JellyfinApiEngine` single — `PlaylistApiClientImpl`, `CollectionApiClientImpl`, `UserDataApiClientImpl` (`writeUserData` funnel + `FavoriteFlagCache`), `HomeLayoutApiClientImpl` (DisplayPreferences pair), `ImageUrlApiClientImpl` (pure URL builders) + `HomeSectionsCachePortAdapter`. Wide `LibraryApiClient` keeps only library-browse/home reads; consumers inject the family they read. Each family's wire bodies exist in exactly one place.

## Data layer

**Library feed seam** — the library/browse family of the former `MediaRepository` union (`LibraryFeed`, the HomeFeed family-seam pattern): folders, latest-media, search (incl. paged), paged-browse, genres, studios, favorites. **The union is GONE** — every consumer injects family seams (`LibraryFeed`, `DetailFeed`, `CollectionOperations`, `MusicCatalogue`, `UserDataChanges`, `UserDataWriteOperations`, `HomeFeed`, plus one-member `SeriesNotificationReads`/`PhotoFolderReads`), all aliased onto one `MediaRepositoryImpl` single. No member carries a default argument (family-seam rule, kept for mockk captures) — seam-typed callers pass defaults explicitly. `markPlayed` only on `UserDataWriteOperations` (drainer uses `recordDrainedPlays`).

**Media freshness ledger** — the media repo's freshness/cache chassis as one ctor-injected collaborator (`MediaFreshnessLedger`): seven-spec cache registry (`MediaCacheGroup`/`MediaCacheSpec`), `StaleReadGroups` ladder, home assembled-payload cache + write-generation funnel (bump-after-operation, one single flight), identity-transition registrations with previous-identity SWR clear, mutation bracket, composite user-data eviction (`invalidateFor` type table), wholesale drop. `MediaRepositoryImpl` pure family forwards over it; outward faces forward. `MediaFreshnessLedgerTest` pins the ladder.

## Home

**Home row module** — everything one `HomeSectionType` knows: descriptor, fetch arm, single-row refresh arm, assembly arm, offline projection, behind one interface in the home row registry. The continue-watching rule (played-row exclusion, hidden ids, NextUp merge) belongs to the ContinueWatching module alone — online and offline consume it from there.

**Row transport registration** — the row module's network counterpart: one registration per `HomeSectionType` stating batch subcall + single-row refresh arm once (wire flags, limits, fold refs), the read, enabled gate, and a nullable refresh arm — a row without one states absence on the registration, not an absent table entry. `HomeRowTransports` in core/network `HomeRowFetchArms.kt`.

**Fetcher cache spec** — fetcher-local list every sub-call cache declares itself on; `invalidateCaches` iterates it (the `cacheSpecs` idiom applied to `HomeSectionsFetcher`): one list so a new sub-call can't be forgotten at clear time (a forgotten clear serves stale badges for a TTL). Suggestions-fallback predicate beside the assembler; both sites call the one function.

**Plugin home content** — plugin rows + curated-hero family as one module the fetcher composes (`PluginHomeContent`): both TTL memos, cache-through reads, resolve-then-map choreography, hero fetch — through the `JellyPlayHomeSectionSources` port, exposing sub-call caches so the fetcher's spec list stays total. Batch schedule, discover generation memo, Seerr TTL gate stay fetcher-side (the batch IS the fetcher's job).

**Items query executor** — /Items family transport half (`LibraryItemsQueryExecutors.kt`): `getItemsQuery` (ONE spec→SDK expansion over `LibraryItemsQuerySpec`, `sendPresenceParams` gate), `getItemsPage` (query + parental fold + `SearchResult`), `toSearchResult` (shared tail fold). Spec-driven sites build→execute; new dimension = one spec field + one executor line. Genuinely different semantics stay bespoke (raw provider-id GET, tags pager, box-set probe). `LibraryItemsQueryExecutorsTest` pins the wire map.

**Home write generation** — data layer's home assembled-payload cache-write token: repo-local monotonic counter (`homeWriteGeneration`), bumped by the funnel AFTER a row-mutation op (dice-roll complete any outcome, single-row refresh success), paired with assembled-payload drop so an in-flight fetch is returned but never pinned. **No token crosses the repo→port→fetcher seam** — branded carrier + `observedGeneration` mirror retired; fetcher's row memo guarded by its own counter inside its roll op, synchronized by hand-off ordering.

**Home content state core** — the eleven `HomeUiState` fields the content list reads travel as one embedded `HomeContentState.Core` value (one-line copy per field; readers qualify through `.core`). Deliberately NOT the `DetailContentState.core` wholesale shape: narrows to content-list fields so an unchanged `Core` stays referentially stable while refresher/dialog fields move; feed/hero/discover/banners remain screen-derived.

**Home feature gate** — one reactive spine for opt-in decorations (stats card, genre rail, presence poll): combine gate flows → dedupe → collectLatest effect once per distinct emission. Presence cadence in `HomePresenceChipsController.poll` (probe/filter/dismiss-memory/loop one owner). ADR-0008 write-effect lift stays rejected. Folded verdicts on `HomeUiState`: HardError keys on `isHardError`, header chip on refresher `fetchFailed` — **a raw `error != null` restatement at either site is a defect**.

**Home user-data reactor** — user-data reaction chain as its own module: debounced `UserDataChanges` collector, pending-flush latch, trailing-edge deferral timer (never inside `refreshJob`), throttle decision, echo/push discrimination. Invariants private to it: every change fans into exactly one silent refresh (never dropped); own-write echo must not re-trigger forced path; drained-play completion echo bypasses throttle + demotion. `HomeRefresher` keeps WHEN, reads reactor through a five-member port; raced-sync flag stays refresher-owned. `HomeUserDataReactorTest` holds thirteen pins.

**HomeDiscovery slice rows** — store's per-user read/restore rows declared on spec tier (`HomeDiscoverySliceRow` + store-blind `HomeDiscoveryUserJsonReads`; star-projection-safe `readInto`/`writeFrom`, no reflection/unchecked casts); `slice()`/`restore()` iterate. 42 of 47 derive; five hand-kept rows documented one-line exclusions, pinned by `HomeDiscoverySpecDerivationTest` (sliceRows == all minus exclusions + restore→re-read round-trip).

## Details

**Detail section module** — everything one detail section knows: admission, optional fetch/enrichment arm, renderer, event projection, behind one interface in the detail section registry (Home row module pattern). Every `DetailSectionKind` module-owned; body routes all kinds through `moduleFor`. `DetailSectionRegistryTest` pins exactly one owner per kind (**a kind claimed by two modules renders twice**) and admission somewhere in the every-family span (**an over-tightened row renders nothing**). Sections riding state arms carry admission + renderer only (`DetailEnrichmentModules.kt`).

**Detail play sequencer** — play click's ordered effects decided once: `DetailPlaySequencer` composes pure `resolveDetailPlayDispatch` + `resolveTrailerPreroll` beside `DetailPlayPolicies`. Input one `DetailPlayContext`; output ordered `DetailPlayEffect`s the screen executes. Process-wide seams arrive as one `MediaDetailPlaybackSeams` ctor bundle, not four mid-body `koinInject` pulls. Raw backdrop getter part of `ArtworkCallbacks` (image domain).

**Detail constructor arms** — nine nullable "unwired" ctor arms as two bundles: `DetailPluginArms` (status store, ONE feature-gate member per ADR-0010, ratings/recommendations/markers apis; nullable because two seams are core:data final classes no no-op stands in for; null folded once inside each arm method) and `DetailBookArms` (toc cache, annotations repo, toc prober, normalized to no-op adapters once in ctor). Silent absence decided at one place per arm. TMDB client + appearance store stay nullable on purpose (single read site each). Tests construct bundles, not nine doubles.

**Detail content state core** — screen content state = VM's `DetailUiState` carried wholesale + genuinely screen-resolved extras (navigation id, persisted season, selected version, downloads slice, resync, manage flag). No fold restates core fields; fields that must not cross named on the type. `DetailContentState.core` carries extras incl. nested `DownloadsExtras`; readers use `state.core.X`, not passthroughs.

**Model-typed enrichment roles** — enrichment seams interface-segregated per family (former 29-member mosaic split): shared `DetailSectionEnrichmentHost` guard/funnel + small role interfaces (plugin gate, ratings, similar/boxset, plugin-data, media/trailer/stream, collection-strip, ambient). Each arm module declares ONLY roles it reads; registries the single wiring points. All roles model-only (wire DTOs decode at role impl — "DTOs stop at the client boundary"); presentation rules stay in the section arm; settings/admin roles keep DTO-in-ViewModel convention.

**Seerr detail view** — movie/tv union as one pure fold `SeerrDetailView.of(movie, tv)` (details commonMain, computed ONCE at screen root — **a descendant re-deriving it is a defect**): content fields movie-first, cast tv-first (`aggregateCredits` wins; empty-but-nonnull does NOT fall through), tv-only fields null on movie leg, asymmetric `imdbId` arms, studios companies-vs-networks fold. `toSeerrSearchItem()` in core:model; request-dialog dispatch movie-first. `SeerrDetailViewTest` pins four shape cases + precedence. `InlineTrailerDialog` twin now one composable.

**Detail load orchestrator** — media-detail load graph behind one module (HomeRefresher pattern): sole writer of content state (VM-side UI writes cross narrow `update` seam — patches, never a second writer), staleness epoch (`DetailLoadGuard`), content-generation latch, session adoption, smart-play resolution, book extras, Seerr companion choreography, plugin gate, enrichment fan-out with role adapters. `DetailViewModel` = flows + `onEvent` facade folding `loader.state` + Seerr request/flags + theme-music groups.

## Downloads

**Download action module** — everything "what can I do to a download" knows: admission (`DownloadActions.availableActions` table, consumed — **a row re-encoding it as a per-status `when` violates the table's contract**), composite resume/retry+enqueue verb (VM + notification receiver both dispatch; lives inside `DownloadRepositoryImpl` — surface ratchet rules out a new queue verb), COMPLETED-is-playable fold, post-action effects (VM-side, DELETE-only single-sited). Row per-status placement stays code keyed on available-action set — **a placement flag table is the rejected shape**. Row interface = item + one `onAction` sink.

**Download action faces** — presentation half: `DownloadActionFaces` carries icon + label res per action split by VOICE, never merged across locales (`bulk`, `bulkAll` — no DELETE, `rowCancel`, `groupPlay`). `TvActionIconButton` owns TV focus chrome once (modifier order pinned); tint default rides `LocalContentColor` — **`Color.Unspecified` means NO colorFilter (intrinsic black), not inherit**. Admission/placement/onClick stay per-surface code. `availableBulkActions` the per-scope set; `DownloadActionFacesTest` pins totality + set/supports agreement.

**Downloads resync actions** — resync/freshness family as one constructed module (`DownloadsResyncActions` from `OfflineResync` + `OfflineRepository` + `DownloadQueue`): four freshness flows, check/resync/force verbs, checking TTL-gate wrapper, eligible-status policy (single-sited private). VM keeps construction + one accessor per family holder; post-action UI effects VM-side. `DownloadsViewModelOwnershipTest` holds member/line ceilings.

**Downloads series-policy actions** — the policy store's two Downloads-screen consumers (gh-181 Ask-suggestion card + ADR-0015 armed list) as one constructed module (`DownloadsSeriesPolicyActions` from `SeriesDownloadPolicyStore` + `DownloadIntake` + `DownloadsStore`): suggestions observe/confirm/dismiss (confirm rides the plain intake — no policy write), the `armedSeries` flow (pure `armedSeriesRows` projection beside the VM — name fallback, `resolveAgainst` against the LIVE global mode, name-then-id order), and `unArmSeries`, the disarm verb's only UI home (`setSeriesPolicy(id, null)`). Mode labels reuse core:ui's `download_sheet_policy_*` — one home for the copy. One-shot feedback rides the holder's `postMessage` sink into the VM's channel; screen-forward resolution stays VM-side. VM keeps construction + one accessor (`seriesPolicyActions`); `DownloadsSeriesPolicyActionsTest` and the ownership ceilings pin it.

**Queue placement verbs** — `moveToFront`/`moveToBack` on the `DownloadQueue` seam; `DownloadRepositoryImpl` computes placement over the DAO snapshot at call time (the authoritative queue state) and persists via the same `updatePriority` write as `setDownloadPriority` — **a caller deriving max/min placement over its own uiState snapshot is the defect** (stale under concurrent list change). `DownloadRepositoryImplPlacementTest` (androidHostTest) pins placement incl. the concurrent-arrival case; the surface ratchet records the sanctioned 11→13 raise.

**Armed series** — the series download-policy state that keeps a series in the auto-download check's universe regardless of local files (gh-225/ADR-0015): an arm row (`series_download_policies`, mode `FOLLOW_GLOBAL` or an explicit override) survives watched-deletion hygiene, so a series with 0 downloaded episodes is still checked every pass. Arming is implicit-on-download (any series-shaped download arms) beside explicit sheet choices. Un-arm: explicit NEVER always; list-management deletion at zero rows; **watch-boundary deletions (auto-delete-after-watch, smart downloads, the #14 offer, the keep-days sweep) never un-arm**. Download candidates never include played or virtual episodes in any mode. A separate watchlist store, coverage-semantics widening, or synced arms are the rejected shapes; "watchlist" is not this repo's word.

## Playback

**Up Next module** — everything "what plays next" knows: queue-vs-sibling advance precedence (queue head over episode sibling), Up Next card projection, one settle-then-consume protocol for activating a queue row. Card and advance read the same verdict. SyncPlay gate the one deliberate split (display projections gate on uiState mirror, advance on manager flag). `SegmentCalculator` + autoplay gate consume the verdict; neither carries queue fragments.

**Manual advance verb** — every user-driven advance as one session verb `userAdvance(variant: UserAdvance)` (sealed `FreshOpen`/`Episode`/`Previous`/`Next`/`WatchedAndSkip`/`QueueItem` beside `PlaybackSession`): engagement reset (`autoplayController.onUserInteraction`) ordered before the variant's verb; FreshOpen additionally resets the auto-advance streak and folds the full `initialize`; binge-streak resets for the other five stay inside UpNext (`playNextManually` owns #17 — source-pinned). The six VM advance arms are one-line variant mappings — **an advance site pair-coding the engagement dance by hand is the defect**. `UserAdvanceTest` pins per-variant ordering.

**End-of-media decision** — end-of-media dispatch as one pure fold `EndOfMediaDecision` composing six tested verdict modules (`SleepTimerBoundaryPolicy`, `AutoPlayController`, `StillWatchingGate`, `UpNextController`, `PostPlaybackActionsController`, cinema chain) into ordered effects; session computes verdicts as facts, executes one arm each. Ladders: sleep-intercept > still-watching > streak-record > advance; cinema > delete-offer > keep-card > close, #17 keep gate single-sited in `closeTail` across both close entries. Composition site `PlaybackSession`; fold pure/internal, not a public seam. `EndOfMediaDecisionTest` truth table.

**Transport routing module** — SyncPlay → cast → local seek/play precedence ladder + per-arm bypass rules (clamp only on user-initiated local seeks, no position-flow write on group/cast arms, resume-skip import on local play arm), behind one interface owned by `PlaybackSession`. Collaborators call router directly; VM transport arms one-line forwards. Ladder asserted behaviorally (recording arms), not source text. `TransportRouter` beside `PipTransportController`; segment-skip dispatch in `SegmentSkipDispatcher` (session constructs, `skipIntro`/`skipSegment` one-line delegates); end-of-media fold session-owned.

**Engine commands funnel** — DIRECT engine commands that never ride the transport ladder (address decode surface, not timeline): playback-speed family (picker + long-press hold-speed gesture, captured restore speed, 250/1000 ms controls-visibility cadence) + scrubbing bracket, behind `EngineCommands` owned by `PlaybackSession` beside `TransportRouter`. VM event arms one-line forwards; "what's playing" reads through `playbackFacts()` snapshot — no caller reaches session manager directly.

**Volume command chassis** — the four volume commands as one `VolumeCommandChassis` in player-contract beside `VolumeCommandTemplates`, composing a small `NativeVolumeSeam` (native residue: read/apply/mute-flag/`preMuteSnapshotLevel`/syncSystemStream/user-changed/restore) and implementing the full `NativeVolumeSurface` (unmute memory chassis-owned, `@Volatile`, audible-only). Containment is the `dispatch` constructor knob (Android engines' open hook vs the desktop alive-guard); snapshot source is `preMuteSnapshotLevel()` seam data (Android system-stream read vs desktop native re-read). All four engines compose it (Exo/VLC/mpv through `ReloadablePlayerEngine` final forwards, desktop by one-line forwards) — **a host hand-copying template bodies or unmute glue is the defect**. `VolumeCommandChassisTest` drives the desktop arm end-to-end without libmpv.

**Player UI commands module** — preference-write choreography (guard → uiState mirror → persist launch → apply, sibling-snapshot-captured-before-write + engine-before-mirror rules) as one module, not per-setter copies. Each setter's divergence stays code, not a flag table. `PlayerUiCommands` owned by `PlaybackSession`; `applyPlaybackPrefChange` lives there. Aspect-ratio belongs here despite persisting nothing (name says UI commands).

**Track selection hub** — `TrackSelectionHelper`: one hub for audio/subtitle selection across engines — picker-row building, side-effecting consequences (`engine.selectTrack`, held-selection guard, per-item persist, cross-episode remembered-track memory + toggle-with-memory latch), `TrackState` slice single home (read-only StateFlow; `resetForItem` clears — track state doesn't survive item switch, series memory does). Pure decision half is split `TrackSelectionPolicy` (pending→stored→scoring→type-specific→matcher→fallback ladder + `external:`/`offline:`/`streaming:` id grammar); hub consumes, never re-encodes. Downloaded-subtitle use is a hub verb: `useDownloadedSubtitle(rowKey)` returns the `UseDownloadedVerdict` (`NotReady`/`ArmedPending`/`Selected`, user message as data) and runs the same chain as a sheet pick (incl. the preview poke); the VM relays verdict→bus and keeps the logcat — **a verdict hand-folded in the VM is the defect**.

**Config delta** — one decision half for all four engines: `EngineConfigDelta.of(old, new)` computes moved config slices; every adapter's `onConfigChanged` switches on flags, not per-field `old != new` ladders. Subtitle carve-out (style change excluding delay riding `SubtitleStyle.offsetMs`) computed inside `of()` from raw configs — never derived from other flags. `subtitleStyleChangedExcludingDelay` feeds Exo + VLC alongside the two mpv hosts.

**Engine event verdict** — event→decision policy both video hosts ride: `EngineEventCoordinator` (player-contract beside `MediaEngine`) folds raw `EngineEventSource` into `EngineDecision`s (guarded play/buffering mirrors, transcode-fallback policy, buffering watchdog, subtitle toasts, pass-out interaction clock); `EngineSessionShell` owns structural half (construction, dispose/reArm, decision fan-out, one-shot session-event pipe). Decision→execution split is the depth: coordinator never writes uiState nor commands engine (657-line suite, flow fixtures + injected clock, zero mocks). Each host pins divergence as `Config` knobs — VOD defaults (`FORCE_DIRECT_PLAY_ONE_SHOT`, `INITIAL_BUFFER_ONLY`), live `EXTERNAL_REQUEST_ONLY` + `EVERY_BUFFERING_EPISODE` + own window. Two adapters, one seam.

**Session spine** — `PlayerSessionManager`: engine stack + load bookkeeping deep module under session root. `loadMedia` spines (`PlaybackSource.Auto` resolve → offline fail-fast gate → `loadOffline`/`loadOnline`, every failure converging on `failLoad`), engine ritual (`initializeEngine`, `activateEngine` lifecycle+PiP wiring, `adoptEngine` config/speed push before load), warm slot (`warmNextEpisode`→`takeWarmResolution`, `WarmNextStream` facts), `reresolveAndSwap` under reload-shaped verbs beside `bindReclaimedEngine`. Outside: five reload variants' choreography (Playback reload coordinator) + position/report family (Session position ledger). Per-load stale-fetch cancels + publish points private to spine. Per-item teardown hooks (`SessionLifecycleHooks`, own file) are session-private: the session provides the bodies behind a private `sessionHooks` delegate, the recording-double seam (`hooksOverride`) unchanged — **a hook body re-exported on the session root is the defect**; the VM's reachable `playbackSession.*` symbol set is exact-set pinned in `ControllerOwnershipTest`. SyncPlay group mode verbs (`setSyncPlayRepeatMode`/`setSyncPlayShuffleMode`) are session arms over its bridge — the VM no longer touches the manager.

**Session position ledger** — position/report family as one module: play-session id resolution (one id per lifecycle for every report/persist), seek latch + report position (fresh seek < 3 s over engine position), stop-report pair with incognito gate + Stop dedup, process-death persistence (wall-clock throttle, store snapshot, coalesced offline-mirror write), lifecycle phase verbs whose pinned orders (stop-inputs snapshot BEFORE any teardown; restore/allocate before persistence-window reset) are private. `SessionPositionLedger` constructed inside session root; session keeps thin delegates; seven internal fields private behind phase verbs.

**Playback reload coordinator** — five reload shapes (engine retry, same-engine retry, transcode fallback, stream change, source switch) as one module, ONE verb `PlaybackReload.reload(variant: ReloadVariant)`. Each variant a sealed case carrying its deltas as data; ordering invariants (position captured before teardown, reporters cancelled before release) private. Session's five entry points one-line forwards; new reload feature adds a variant, not another choreography copy. Shared rebind tail stays session-owned (cinema/reclaim reuse). `PlaybackReloadTest` pins variant→delta folds.

**Cinema pre-roll sequencer** — cinema-mode chain as session-root state: `CinemaIntroContext` (original `initialize` args + intro queue + cursor, `@Volatile`), `beginCinemaMode`, `loadCinemaIntro` (`trackProgress = false`: intros not library history — no server reporting/segment/next-episode/trickplay bookkeeping while media session + position tracking rebind), idempotent `advanceCinemaIntro` whose restore arm clears context before recursive `initialize` (`allowCinemaMode = false`) so chain can't re-enter. VM arms call session, own no sequencing. **Deliberately not a standalone module** — bodies need the full session graph, extraction fails ADR-0012's shallow-module test; re-proposing it re-litigates that ADR.

**Player preference leaf table** — ONE home for "which preference feeds which player uiState leaf": typed rows (aggregate read, optional state read, write lens, engine-config rebuild flag), plain data + lambdas, no reflection. Three strategies read it: seed (load-time unguarded fold), projector (change-time guarded diff, one uiState copy per changed leaf), fanout (rebuild-reaction diffs). Only mapping between prefs and player uiState leaves. Non-rows stay hand-written (adaptiveBitrateEnabled leaf, HDR-aware subtitle-style resolution, PIN pair one-copy double write, non-leaf reactions). `PLAYER_PREF_LEAVES` table; `PlayerPrefsSeed`/`SettingsProjector`/`PlayerPrefsFanout` strategies.

**Player sheet module** — everything one player sheet knows: entry points (chip/overflow/gear/cross-sheet links), commands, slice region — registered in a sheet registry at Home-row-module grain (feature-grain, NOT ADR-0009's rejected settings-group grain). Four sheets registry-owned (Hdr, Render, SubtitleHub, PlaybackMode); SubtitleHub reads `SheetsSessionSlice` via `SubtitleHubSheetModule` with per-tab input bundles. Remaining sheets route through router `when`. Hub remote-subtitle fetch starts at composition; config-change restore re-entry refetches. Sheet tests derive from `PlayerSheetRegistry.all` — **a hand sheet list there is the defect shape**.

**Player parameter bundles** — overflow menu takes `capabilities: EngineCapabilities` + one `PlayerOverflowMenuActions` bundle instead of re-flattening capability projection into per-call-site booleans; `ticksToFraction` (state/) the one home for seek-bar ticks→fraction clamp policy.

**mpv load plan** — per-request mpv option ladder as one pure plan `MpvLoadOptionsPlan`: request → ordered (option, value) writes (TLS reset trio, normalized + blank-skipped language lists, User-Agent extraction, header persistence discipline — reset unconditional in BOTH spellings: `REPLACE_LIST` for Android/desktop, `RESET_AND_APPEND` where transport supports list-append — readahead). Each engine supplies only transport seam; desktop shares ladder (`MpvDesktopEngineAndroidParityTest` pins).

**mpv option vocabulary home** — mpv option vocabulary (`MpvConfigMapping`, `MpvConfigApplier`, `MpvErrorTaxonomy`, `MpvAudioMappings`, `MpvLoadOptionsPlan`, `MpvProperties`) in core/player-contract beside `MpvPropertyIntake`/`MpvStyleMapping`; engine choreography (`MpvCore`, `MpvBinding`, host engines) in feature/player-video. Files keep `feature.player.video` package — deliberate split package (one package spanning two modules) to avoid import churn; re-homing is per-file rename, not API break. The desktop mpv host rides the same geography: engine/binding/lib/render/software-engine/audio-chain live in player-video jvmMain under the `desktop.player` split package, the parity suite beside them; the factory stays app-side (it wires the app-owned `EngineActivityRecorder` session harness). `MpvAudioMappings` three helpers public (`internal` is module-scoped to player-video; `MpvCore` consumes across edge).

**Stats publish guard** — engines' video-stats change-guard (last-value cache, scalar-change predicate, forced periodic full re-read, publish funnel) as one `StatsPublishGuard` in player-contract beside `MpvStatsProjection`, parameterized by read source; published-shape comparison (HDR fold computed before dedup guard) the pinned contract. Exo + mpv ride it.

**Audio shell seam** — app shell's read surface over audio family: `ShellAudioSurface` (narrow interface) instead of concrete androidMain `AudioPlaybackManager` crossing into shell code. Finished: remote-control dispatcher reads `AudioRemoteControlSurface`, playback service `AudioServiceSurface`, focus surface `AudioFocusCommands`, shortcut manager `NowPlayingSurface` — manager implements faces, only Koin modules name concrete class. Crossfade hand-off tail in `AudioCrossfadeHandoff` beside `AudioCrossfader` (crossfader decides, handoff owns stop-report→commit→engine swap→session rebuild).

**HDR mode verdict** — playback-mode derivation (`resolveHdrPlaybackMode`) + HDR family vocabulary (dovi/hdr10+/hlg) in `HdrOutputPolicy`; sheet renders verdict, metadata row labels through one family parser, engines consume same decision. `hdrFamilyOf` the one parser feeding `hdrContentFromStreams`/sheet/metadata row; `HdrPlaybackModeTest` pins JVM lane.

**mpv core** — commonMain mpv engine choreography: load, seek, track selection, subtitle style, property intake, ordering rules. Platform code is an **mpv binding** — adapter over platform handle (Android JNI, desktop libmpv) satisfying the binding seam; two bindings make it real, a fake binding tests core without libmpv.
